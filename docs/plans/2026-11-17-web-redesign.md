# DevShoes 화면을 다크 갤러리형으로 전면 재구성합니다

> 작성일: 2026-11-17
> 범위: 화면 구성, 디자인 토큰, 애니메이션, 이미지 로딩. 데이터 수집 방식(`lib/api.ts`의 파싱)은 그대로 둡니다.

## 방향

검은 바탕 위에 신발 사진을 주인공으로 세우고, 강조색은 볼트 라임 한 가지만 아껴 씁니다. 첫 화면은 큰 제목과 실제 신발 사진이 흐르는 기울어진 벽으로 시선을 잡고, 아래 목록은 한 개의 넓은 그리드와 상단 도구 막대로 단순하게 정리합니다. 움직임은 많이 넣되 모두 의미가 있는 곳에만 둡니다. 카드를 누르면 카드 사진이 상세 화면 자리로 날아가 커지고(View Transitions), 필터를 바꾸면 카드가 새 자리로 미끄러져 재배치됩니다.

## 현재 화면에서 고칠 점

| 항목 | 지금 상태 | 바꿀 방향 |
|---|---|---|
| 이미지 | 원본 사진(1~4MB, 가로 최대 5,712px)을 `unoptimized`로 89장 그대로 불러옴 | Next 이미지 최적화를 켜서 카드 크기에 맞는 WebP로 받음. 같은 사진 640px 기준 3.8MB에서 17KB로 줄어드는 것을 로컬에서 확인 |
| 사진 배경 | 흰 배경, 회색 배경, 상자 위 사진이 섞여 검은 카드 안에서 흰 사각형으로 튐 | 같은 사진을 흐리게 깔아 빈 공간을 사진 자신의 색으로 채움 |
| 첫 화면 | 배지와 설명 한 줄뿐이고, 설명 문구는 blur 애니메이션 때문에 한동안 흐리게 보임 | 큰 제목, 숫자 지표, 신발 사진 벽 |
| 목록 구조 | 브랜드 29곳을 섹션으로 나눠, 1~2켤레짜리 섹션 제목이 22번 반복됨 | 한 개의 그리드 + 가로로 넘기는 브랜드 레일 |
| 진행 막대 | 180일 기준이라 89켤레 중 49켤레가 가득 찬 막대로 보임 | 실제 승인 기간(대부분 364일) 대비 남은 비율로 계산 |
| 상세 열기 버그 | 카드 memo 비교가 클릭 함수를 무시해서, Nike로 필터한 뒤 "Dev 729"를 누르면 "Dev1011"이 열림(라이브 사이트에서 재현) | 신발 ID로 선택 상태를 저장하고 클릭 함수를 고정 |
| 애니메이션 | `filter: blur`를 애니메이션에 써서 프레임 부담이 큼 | transform과 opacity만 움직임 |

## 참고한 디자인

- 치지직(getdesign.kr): 살짝 푸른 기가 도는 다크 뉴트럴 단계, Pretendard, 자간 -0.3px, 8~24px 둥근 모서리 단계를 기준으로 삼았습니다.
- ORYZO AI(styles.refero.design): 어두운 바탕에 제품 하나를 띄우고 강조색은 한 가지만 쓰는 방식, 1px 헤어라인과 알약 모양 컨트롤을 참고했습니다.
- Astryx: 이 프로젝트는 Tailwind v4로 직접 만든 스타일을 쓰고 Astryx는 StyleX 기반이라 컴포넌트는 가져오지 않고, 모션 원칙(자주 쓰는 호버는 빠르게, 드롭다운은 즉시 닫기)만 따릅니다.

## 디자인 토큰

| 구분 | 값 |
|---|---|
| 바탕 | `#0A0B0C` 페이지, `#111214` 카드, `#17191B` 떠 있는 면, `#202224` 컨트롤 |
| 선 | 흰색 7% 기본, 12% 강조 |
| 글자 | `#F4F5F6` 기본, `#B3B9C4` 보조, `#7C8391` 흐림, `#565C67` 비활성 |
| 강조 | 볼트 라임 `#D4FA3C`, 그 위 글자 `#0A0B0C` |
| 상태 | 90일 넘게 남음: 볼트, 90일 이내: `#FFB224`, 30일 이내: `#FF6A3D`, 만료: 회색 |
| 글꼴 | Pretendard Variable 하나로 통일(Geist 제거), 숫자는 tabular-nums |
| 모서리 | 8, 12, 16, 20, 24px와 알약형 |

카드의 D-day 숫자는 평소 흰색으로 두고, 90일 이내와 30일 이내일 때만 상태색을 입혀 급한 신발만 눈에 띄게 합니다.

## 화면 구성

**헤더**: 볼트색 로고 마크와 DevShoes 글자, 오른쪽에 원본 목록과 GitHub 링크. 스크롤하면 반투명 배경과 헤어라인이 생기고, 모바일에서는 아래로 스크롤할 때 숨습니다. 헤더가 숨으면 목록 도구 막대도 같이 위로 붙습니다.

**히어로**: 왼쪽에 "아직 출시되지 않은 / 개발 신발 89켤레" 두 줄 제목(숫자는 데이터에서 계산), 설명, 목록 보기와 원본 목록 버튼, 지표 네 개(전체, 브랜드, 최근 30일 신규, 30일 안에 만료). 오른쪽에는 최신 신발 사진 타일이 세 줄로 서로 반대 방향으로 흐르는 3D로 기울인 벽을 둡니다. 모바일에서는 벽이 제목 아래로 내려갑니다.

**목록**: 제목 "전체 목록"과 개수, 상단에 붙는 도구 막대(검색, 상태 선택, 정렬, 필터 버튼), 그 아래 브랜드 레일, 선택한 필터 칩, 카드 그리드(1, 2, 3, 4열). 기존의 브랜드별 섹션과 "최신 등록" 섹션은 없애고, 등록 30일 이내 신발에 NEW 표시를 붙입니다. 최신순이 기본 정렬이라 새 신발은 맨 앞에 옵니다.

**카드**: 사진 판(흐린 배경 위에 사진 전체를 담음), 브랜드, 제품명 두 줄, 유형과 종목, D-day와 만료일, 남은 기간 막대.

**상세**: 데스크톱은 왼쪽 큰 사진, 오른쪽 정보의 두 칸 패널, 모바일은 전체 화면 패널입니다. 남은 일수를 크게 보여 주고, 인증 시작일부터 만료일까지의 기간 막대에 오늘 위치를 표시합니다. 모델 번호, 대체 모델 번호, 종목을 정리하고, 이전과 다음 이동(화살표 키, 모바일 좌우 스와이프)과 사진 확대를 유지합니다. 포커스를 패널 안에 가두고 닫으면 원래 카드로 돌려줍니다.

**필터 패널**: 데스크톱은 오른쪽에서 열리는 서랍, 모바일은 바텀시트입니다. 상태, 브랜드, 종목, 유형을 체크박스 목록으로 고르고, 모바일에서는 정렬도 여기서 바꿉니다.

**푸터**: 큰 DevShoes 글자, 갱신 시각, 링크, 기존 면책 문구.

## 애니메이션

| 대상 | 방식 | 시간과 곡선 |
|---|---|---|
| 히어로 제목 | 한 줄씩 12px 아래에서 Fade in | 줄당 400ms, 80ms 간격, ease-out |
| 히어로 지표 | 숫자가 0부터 올라감(하이드레이션 전에는 숨김) | 900ms, ease-out |
| 사진 벽 | 줄마다 다른 속도로 무한히 흐름, 마우스를 올리면 멈춤 | 64~92초, linear |
| 히어로 스크롤 | 스크롤에 맞춰 제목이 올라가며 흐려지고 벽이 어두워짐(scroll-driven, 지원 브라우저만) | 스크롤 연동 |
| 카드 등장 | 화면에 들어올 때 16px 아래에서 Fade in, 열 순서대로 60ms 간격 | 500ms, ease-out |
| 카드 호버 | 4px 떠오름, 사진 1.04배, 커서를 따라가는 빛 | 200~300ms |
| 필터와 정렬 변경 | 카드가 새 자리로 이동(View Transitions) | 350ms |
| 카드에서 상세로 | 카드 사진이 상세 사진 자리로 날아가며 커짐, 배경 Fade | 열 때 450ms ease-out, 닫을 때 300ms |
| 상세 패널 | Scale 0.95에서 1과 Fade | 200ms 들어옴, 150ms 나감 |
| 필터 서랍, 바텀시트 | 오른쪽 또는 아래에서 Slide in, 배경 Fade | 300ms 들어옴, 250ms 나감 |
| 체크박스 | 체크 선 그리기 | 200ms, ease-in-out |
| 상태 선택 | 선택 표시가 미끄러져 이동 | 250ms |
| 정렬 메뉴 | Scale 0.97에서 1과 Fade, 닫을 때는 즉시 | 150ms |
| 로딩 | 회전 | 1회전 800ms, linear |

나갈 때는 ease-in으로 더 짧게 끝내고, `prefers-reduced-motion`에서는 이동과 크기 변화를 빼고 짧은 Fade만 남깁니다. View Transitions를 지원하지 않는 브라우저에서는 일반 CSS 애니메이션으로 열고 닫습니다.

## 바꿀 파일

- 설정: `next.config.ts`(이미지 캐시 31일), `src/app/layout.tsx`(Pretendard, theme-color)
- 스타일: `src/app/globals.css` 전면 교체, `src/styles/tokens.ts`는 상태색과 모션 값만 남김
- 화면: `page.tsx`, `loading.tsx`, `Header`, `HeroSection`(사진 벽, 숫자 애니메이션 포함), `ShoeGrid`, `ShoeCard`, `ShoeModal`, `SearchBar`, `EmptyState`, `Footer`, `ScrollToTop`
- 필터: `SidebarFilter`, `MobileFilter`, `MobilePresetChips`, `BottomSheet`를 `FilterPanel` 하나와 `BrandRail`, `StatusSegment`, `SortMenu`로 정리
- 유틸: `utils/progress.ts`(승인 기간 기준), `utils/date.ts`(짧은 날짜 형식), `hooks/useFilters.ts`(상태별 개수)
- 문서: `CLAUDE.md`, `README.md`의 디자인 설명

## 확인 방법

1. `npm run lint`와 `npm run build`가 통과합니다.
2. 데스크톱(1440px)과 모바일(375px)에서 히어로, 목록, 필터, 상세를 열어 화면이 잘리거나 겹치지 않는지 봅니다.
3. Nike로 필터한 뒤 카드를 눌러 같은 신발이 열리는지 확인합니다.
4. 상세에서 화살표 키, ESC, 확대가 동작하는지 확인합니다.
5. reduced-motion을 켜고 움직임이 Fade만 남는지 확인합니다.

## 위험과 대응

- Vercel Hobby 요금제의 이미지 변환 한도(월 5,000회)를 넘을 수 있습니다. 사진 ID가 바뀌지 않으니 캐시를 31일로 늘리고 크기 종류를 줄여, 한 달 변환 수를 1,000회 안쪽으로 예상합니다. 한도에 걸리면 `unoptimized`로 되돌리면 됩니다.
- Pretendard는 jsDelivr CDN에서 받습니다. CDN이 막히면 시스템 글꼴(Apple SD Gothic Neo, 맑은 고딕)로 보입니다.
- 브랜드별 섹션이 사라집니다. 브랜드 레일에서 한 번에 고를 수 있어 찾는 수고는 비슷하다고 판단했지만, 섹션 구성을 다시 원하면 정렬 옵션에 "브랜드순"을 추가하는 방식으로 되살릴 수 있습니다.
